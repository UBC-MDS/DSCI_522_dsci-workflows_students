Docker & Docker Compose Cheatsheet

Quick Reference Guide for Docker Containerization

1 Docker Basics

1.1 Important Notes

WarningCommand Line Sensitivity

Command lines are very sensitive to whitespace and quotation marks! Pay close attention to syntax.

TipVersion Tags

Don’t use the TAG latest for images. Always use specific version tags instead for reproducibility.

1.2 Basic Docker Run

  • Example command to run a docker container:
docker run \
    --rm \
    -p 8788:8787 \
    -e PASSWORD="apassword" \
    rocker/rstudio:4.4.2
  • Explanation for the command above:
    • --rm: Automatically remove container when it exits
    • -p 8788:8787: Map host port 8788 to container port 8787
    • -e PASSWORD="apassword": Set RStudio password to be “appassword”
    • rocker/rstudio:4.4.2: Image name with specific version tag
  • After the docker image successfully runs, you can access RStudio at: http://localhost:8788

1.3 Essential Docker Commands

Task Command
Pull an image from Docker Hub docker pull <image_name>:<tag>
List all local images docker images
List running containers docker ps
List all containers (including stopped) docker ps -a
Remove an image docker rmi <image_name>:<tag>
Remove a container docker rm <container_id>
Stop a running container docker stop <name or container_id>
Run a command in a running container docker exec -it <name> <command>

Common flags:

Flag Description
--rm Automatically remove container when it exits
-d Run the container in the background (detach)
--name <name> Give the container a name, to use instead of its ID
-it Interactive terminal (combine -i and -t)
-p <host_port>:<container_port> Port mapping
-v <host_path>:<container_path> Volume mounting
-e <VAR>=<value> Set environment variable
--platform <platform> or -p <platform> Specify platform (e.g., linux/amd64)

2 Docker Compose

2.1 Why use Docker Compose?

We use docker-compose.yml file because it simplifies the process of typing complex docker run commands.

2.2 Basic Commands

Task Command
Start docker container docker compose up
Stop docker container Ctrl + C (then docker compose rm)

2.3 Code we run in class: docker-compose.yml practice

Step-by-step instructions:

  1. Please first cd to a local folder of your choice, don’t put all files in your home directory!
# Example `cd` command: 
cd /Users/skysheng/Desktop/github/dsci522
  1. Make a new folder called demo_docker (or any other name you like)
mkdir demo_docker
  1. Move into that folder we just created
cd demo_docker
  1. Create a docker-compose.yml file using nano
nano docker-compose.yml
  1. Copy and paste the following code into the docker-compose.yml file. Local port is set at 8789, password is set to password, username is rstudio.
services:
  analysis-env:
    image: rocker/rstudio:4.4.2
    ports:
      - "8789:8787"
    volumes:
      - .:/home/rstudio/project
    environment:
      PASSWORD: password
    deploy:
      resources:
        limits:
          memory: 5G
  • You can also create this file using Graphical user interface (GUI) like VSCode.
  • If you used nano to create this file, you need to press Cntrl + X to attempt exit, by default it will ask you to save the file. Press Y and then press Enter to save the file.
  1. Print out the content of the file to make sure it is correct.
cat docker-compose.yml
  1. Launch the container using docker compose files.
docker compose up

  1. After the container is launched, your terminal will be hanging. You can open your browser and go to http://localhost:8789 to access RStudio.

  2. To stop the container, you need to type Cntrl + C in the terminal where you launched the container, and then type:

docker compose rm

3 Dockerfile

A Dockerfile contains instructions for building a custom Docker image.

Basic structure:

# Start with a base image
FROM base_image:tag

# Copy files
COPY local_path container_path

# Run commands
RUN command

# Set environment variables
ENV VAR_NAME=value

3.1 Code we run in class: Dockerfile practice

We build an image that has our Python packages from uv.lock installed. We work like the textbook suggests: start small, build the image, try the next command inside the container, and only then add it to the Dockerfile.

Step-by-step instructions:

  1. Please first cd to a local folder of your choice, don’t put all files in your home directory!
# Example `cd` command:
cd /Users/skysheng/Desktop/github/dsci522
  1. Make a new folder called demo_docker (or any other name you like), and move into it
mkdir demo_docker
cd demo_docker
  1. Create a uv project with one package. This makes pyproject.toml, .python-version and uv.lock (see the uv cheatsheet for what each file holds).
uv init --bare
uv python pin 3.14
uv add "pandas==3.1.1"
  1. Print out the files to make sure they are correct.
cat pyproject.toml
cat .python-version
  1. Create a Dockerfile using nano (or a GUI like VS Code).
nano Dockerfile
  1. Copy and paste the following code into the Dockerfile. It starts from the official Python image (the same Python version as .python-version), copies the uv program into the image, and copies our three uv files into the folder /home/project.
FROM python:3.14-slim

COPY --from=ghcr.io/astral-sh/uv:0.13.7 /uv /uvx /usr/local/bin/

WORKDIR /home/project
COPY pyproject.toml uv.lock .python-version ./
  • If you used nano to create this file, you need to press Cntrl + X to attempt exit, by default it will ask you to save the file. Press Y and then press Enter to save the file.
  1. Build the docker image locally:
# Build the docker image locally, with the tag name `testing_cmds`.
# pay attention to the dot at the end of the command!
docker build --tag testing_cmds .
  1. Run the image you just built, and open a terminal inside the container:
docker run --rm -it testing_cmds bash
  1. Inside the container, test the command that installs our packages, and check that it worked. --locked makes uv sync stop with an error if uv.lock does not match pyproject.toml.
uv sync --locked
uv run python -c "import pandas; print(pandas.__version__)"

  1. If the above commands work, exit the container by typing exit.

  2. Update the Dockerfile to include the newly tested command. We also tell uv to put the environment in /opt/venv instead of /home/project/.venv, so it is not hidden when we later mount our project folder over /home/project, and we put /opt/venv/bin first on the PATH, so python means the environment’s Python.

FROM python:3.14-slim

COPY --from=ghcr.io/astral-sh/uv:0.13.7 /uv /uvx /usr/local/bin/

WORKDIR /home/project

ENV UV_PROJECT_ENVIRONMENT=/opt/venv
COPY pyproject.toml uv.lock .python-version ./
RUN uv sync --locked
ENV PATH="/opt/venv/bin:$PATH"
  1. Re-build the docker image (same command as step 7), then check that pandas is installed:
docker build --tag testing_cmds .
docker run --rm testing_cmds python -c "import pandas; print(pandas.__version__)"

  1. Iterate through steps 7 to 12 (build the image, run the container’s terminal, test a new command, add it to the Dockerfile, build again …) until you are happy with your Dockerfile.

  2. Use the image with your project folder mounted, so the container can see your files:

docker run --rm -it -v "/$(pwd)":/home/project testing_cmds bash
TipAdding a package later

Add it on your computer with uv add <package>, which updates pyproject.toml and uv.lock, then rebuild the image (step 7).

4 uv + Docker + GitHub Actions Workflow

  1. uv init --bare & uv python pin
  2. uv add your packages (this writes pyproject.toml and uv.lock)
  3. Push pyproject.toml, uv.lock and .python-version to GitHub (not .venv/)
  4. Write Dockerfile
  5. Create docker-compose.yml
  6. Push to GitHub
  7. Add GitHub Actions workflow yml file
  8. Add Docker Hub Personal Access Token (PAT)
  9. Configure GitHub Secrets
  10. Workflow runs (auto/manual)
  11. Check Docker Hub for new image
  12. Locally, docker pull new image
  13. Locally, command line docker run
