- **`WORKDIR /workspace`**:

  - The container is Linux, so packages must be installed for the container's environment.
  - When the host project folder is mounted into the container, the host's `.venv` is ignored by `uv` inside the container.
- **Copying project files**:
  - The demo copied `pyproject.toml`, `uv.lock`, and `.python-version` into the container.
  - Then it ran `uv sync --locked`.
- **`uv sync --locked`**:
  - `--locked` is a guardrail.
  - It fails if `uv.lock` and `pyproject.toml` are out of sync.
  - It makes the build check that the locked dependencies match the project definition.
- **SSH setup**:
  - The demo installs `openssh-server`.
  - The `Dockerfile` ends with `CMD ["/usr/sbin/sshd", "-D"]`.

### 3. Building and running containers

- **Building the image**:
  - `docker build --tag docker-uv-renv .`
  - The `.` means “look for a `Dockerfile` in the current working directory.”
  - The image was named `docker-uv-renv`.
- **Running interactively**:
  - `docker run --rm -it docker-uv-renv bash`
  - `--rm`: remove the container after exiting.
  - `-it`: interactive mode plus a terminal.
  - `bash`: start a Bash shell inside the container.
  - The prompt changed to something like `root@<container-id>:/workspace#`, showing that the user is now inside the container.
  - `pwd` showed `/workspace`.
  - `whoami` showed `root`.
- **Python inside the container**:
  - Plain `python` was not found.
  - The working command was `uv run python`.
  - This matters because the project uses `uv` as the Python environment manager.
  - A prebuilt Python container may have a system `python`, but packages installed by `uv` will not necessarily be visible to that system `python`.
- **Mounting the project folder**:
  - `docker run --rm -v "$(pwd):/workspace" -it docker-uv-renv bash`
  - This mounts the host's current working directory into the container's `/workspace` folder.
  - The instructor demonstrated that `touch hello.py` inside the container immediately created `hello.py` on the host.
  - He compared this to a network share drive: both sides see the same files.
- **File-conflict warning**:
  - If the same file is open in two places, saving in one place can overwrite the other.
  - Some IDEs have a “revert file” action to refresh the open buffer.
  - The instructor advised reverting the file before editing if the file may have changed elsewhere.
  - Overwriting can lose changes, similar to a Git conflict but without Git's merge process.
- **Why use volumes instead of copying files into the image?**
  - `COPY` in a `Dockerfile` copies files at build time.
  - Active analysis files change often; rebuilding the image after every change would be slow.
  - Mounted volumes reflect changes immediately in both directions.
  - It avoids putting Git credentials or SSH keys into the image.
  - The container is reset when it is stopped and restarted, so secrets baked into the image would remain and be shared with anyone who pulls the image.
  - Mounting a public SSH key as `authorized_keys` is safer than storing private credentials in the container.
- **Container reset as a sandbox**:
  - Changes inside the container are discarded when the container is stopped and started again, unless the changes are in mounted volumes.
  - This makes the container useful for experimenting with risky installs or commands.
  - The instructor said it is a good place to test something like `rm -rf /`, but warned emphatically not to run that on a real computer.

### 4. Docker Compose

The new topic was [Docker Compose](https://ubc-dsci.github.io/reproducible-and-trustworthy-workflows-for-data-science/lectures/containers-docker-compose.html). A `docker-compose.yml` file stores the settings that would otherwise be typed as a long `docker run` command.

- **Why use Docker Compose?**
  - Long `docker run` commands are hard to edit in a terminal.
  - Copy-pasted commands can break due to spaces, line breaks, or missing continuation characters.
  - A compose file is easier to document, version control, and reuse.
  - The same file can be used across macOS, Linux, and Windows.
- **Demo compose file**:
  - The class used [`docker-compose.yml`](https://github.com/chendaniely/2026-11-25-docker-validate/blob/main/docker-compose.yml).
  - It defined one service named `analysis-env`.
- **Mapping compose fields to Docker commands**:
  - `services:` lists the containers to run.
  - `build: .` builds the image from the `Dockerfile` in the current folder.
  - `image: docker-uv-renv` names the image, like `docker build --tag docker-uv-renv`.
  - `ports: - "2222:22"` maps host port `2222` to container port `22`.
  - `volumes: - .:/workspace` mounts the host project folder into `/workspace`.
  - `volumes: - ~/.ssh/id_ed25519.pub:/root/.ssh/authorized_keys:ro` mounts the public SSH key as the container's authorized keys, read-only.
- **Port numbers**:
  - The first number is the host port used on the computer.
  - The second number is the port used inside the container.
  - SSH inside the container listens on port `22`.
  - The host port was `2222` to avoid interfering with the host's own port `22`.
  - The instructor warned that port `22` is commonly used for real SSH connections, so it should not be overwritten accidentally.
  - If a service such as RStudio or Jupyter is running in a container, the host port and container port may be the same or different; the important thing is knowing which side you are connecting to.
- **Volumes and security**:
  - `.:/workspace` makes the current project folder available inside the container.
  - The SSH public key mount allows SSH logins without storing private credentials in the image.
  - `ro` makes the mounted key read-only inside the container.
- **Service name, image name, and container name**:
  - The service is `analysis-env`.
  - The image is `docker-uv-renv`.
  - Docker Compose names the running container using the project folder and service, for example `2026-11-25-docker-validate-analysis-env-1`.
  - `docker compose exec` uses the service name, not the full container name.
  - You can run multiple containers from the same image as long as their service names or container names are different.
- **Docker Compose commands**:
  - `docker compose build`: build the image described in the compose file.
  - `docker compose up --detach`: start the service in the background.
  - `docker ps -a`: inspect running and stopped containers.
  - `docker compose exec analysis-env bash`: run a command in the already running container.
  - `docker compose down`: stop and remove the container and its network.
  - `docker compose run --rm analysis-env uv run python`: run a one-off command in a new container and remove that container afterward.
- **Memory warning**:
  - Containers are like other computers and use RAM.
  - Running many containers at once can consume a lot of memory.
  - The instructor advised being diligent about stopping containers when they are no longer needed.
- **Use beyond MDS**:
  - The instructor mentioned that many open-source tools are deployed with Docker Compose files, for example `N8N`, `Jellyfin`, and a personal finance application.
  - Docker Compose is therefore a general skill, not only a data-science workflow detail.

### 7. Data validation with `pointblank`

The session previewed the [data validation chapter](https://ubc-dsci.github.io/reproducible-and-trustworthy-workflows-for-data-science/lectures/data-validation-python-pointblank.html) and used the [pointblank for Python documentation](https://posit-dev.github.io/pointblank/) package.

- **Packages**:
  - The class discussed `pandera` and `pointblank` as validation tools.
  - The live demo used `pointblank`.
  - The demo also used `palmerpenguins` to load the Palmer penguins dataset.
  - `pandera`, `pointblank`, and `palmerpenguins` were added to the project for the validation part.
- **Loading the data**:
  - `from palmerpenguins import load_penguins`
  - `penguins = load_penguins()`
- **Missing-value exploration**:
  - `pb.missing_vals_tbl(data=penguins)`
  - This reports where missing values occur.
  - The instructor said it can be useful to inspect missingness before writing formal checks.
  - Missingness should often be treated as a separate analysis from value checks.
- **Validation object**:
  - A validation starts with `pb.Validate(...)`.
  - The demo used:
    - `data=penguins`
    - `label="Penguin measurements"`
    - `thresholds=(0.01, 0.05, 0.10)`
  - The thresholds mean:
    - at least 1% failure is a warning,
    - at least 5% failure is an error,
    - at least 10% failure is critical.
- **Checks shown in class**:
  - `col_vals_in_set(columns="species", set=["Adelie", "Chinstrap"])`
    - Checks that `species` contains only the listed values.
    - The live demo intentionally omitted a species so the report would show a failure.
  - `col_vals_between(columns="bill_length_mm", left=30, right=60, na_pass=True)`
    - Checks that measured bill lengths are within a plausible range.
    - `na_pass=True` allows missing values to pass this value check.
  - `rows_distinct()`
    - Checks for duplicate rows.
    - Useful when sensor readings or repeated entries should be unique.
- **Running the checks**:
  - `.interrogate()` runs the chained checks and returns a report.
  - The report shows which checks passed or failed and how close they are to the thresholds.
- **Splitting passing and failing rows**:
  - `values.get_sundered_data(type="pass")` returns rows that passed the checks.
  - `values.get_sundered_data(type="fail")` returns rows that failed at least one check.
  - This supports team workflows: one person can continue with the passing data while another person fixes or investigates the failing rows.
  - The resulting data frames can be saved to files for handoff.
- **Where validation belongs in an analysis**:
  - Data checks are not necessarily one block of code.
  - They can happen after cleaning and before modeling.
  - They can happen in multiple places as the analysis progresses.
  - The instructor said this would be part of the next week's assignment, along with breaking code into smaller pieces.
- **Real data considerations**:
  - Health data may contain impossible values, such as “pregnant men,” if such a variable exists.
  - Survey data may use codes such as `99` to represent missing values.
  - Plausible bounds can be useful for variables such as BMI or physical measurements.
  - Missing values should often be checked separately, by column and by row.
