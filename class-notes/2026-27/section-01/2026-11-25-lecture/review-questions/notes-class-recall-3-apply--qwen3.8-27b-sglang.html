1. Building the milestone image: repository, Dockerfile, uv, and mounted runs (29 Customizing and building containers)

00:00:00–00:44:42

  • Q: You are starting the milestone repository on your laptop. In order, which commands give you the project files and generate uv.lock before you build the image?
    • A: Run git clone git@github.com:chendaniely/2026-11-25-docker-validate.git, then cd 2026-11-25-docker-validate, and then run uv sync in the folder containing pyproject.toml. uv sync creates the .venv virtual environment and the uv.lock file; those are the files the Dockerfile can later copy. (00:33:34)
  • Q: You copied the reference Dockerfile into your project and are about to commit it. What habit should you follow before pushing?
    • A: Do not blindly copy the template; understand the pieces you are putting into the repository. A commit with your name on it can be asked about in detail, so make sure you can explain the code or configuration you committed. (00:08:51)
  • Q: You are converting the demo Dockerfile for a Python-only project and want to reduce the image download for anyone who pulls it. What base-image change should you make, and why?
    • A: Use a smaller base image, such as a plain Ubuntu image, instead of the demo’s rocker/r-ver:4.6.2 R base. The R base works for Python work, but it takes up more storage and makes the download longer for people using the container. (00:09:57)
  • Q: You need git and nano available inside the Linux container. What Dockerfile instruction installs them?
    • A: Use RUN apt-get update && apt-get install --yes git nano. RUN executes terminal commands inside the container’s Linux operating system, and apt-get is the Ubuntu package installer. (00:11:02)
  • Q: You need uv inside the image and you want the image to control the uv version. Which Dockerfile line does the demo use, and what should you check if you swap in a pre-built uv image instead?
    • A: The demo uses COPY --from=ghcr.io/astral-sh/uv:0.13.7 /uv /uvx /usr/local/bin/ to copy the uv binaries into the image. If a pre-built uv image is used instead, you need to find where uv is installed in that image, because pyproject.toml does not track the version of uv. (00:15:12)
  • Q: You add WORKDIR /workspace before COPY and RUN lines. What does Docker do when that folder does not already exist?
    • A: Docker creates /workspace and sets it as the working directory, acting like mkdir plus cd. Later commands and the container prompt start in that project folder instead of the operating-system root. (00:16:32)
  • Q: You mount your project folder into the container, and the host .venv is visible in /workspace. With UV_PROJECT_ENVIRONMENT=/opt/venv set, predict which virtual environment uv uses inside the container.
    • A: It uses /opt/venv, not the mounted host .venv, because the host virtual environment is tied to the host operating system and CPU. The container is another Linux machine, so uv installs packages into the container-specific location. (00:18:38)
  • Q: Your Dockerfile sets ENV UV_PROJECT_ENVIRONMENT=/opt/venv, but an SSH login into the container still does not see that variable. What Dockerfile line fixes the login behavior?
    • A: Add RUN echo "UV_PROJECT_ENVIRONMENT=/opt/venv" >> /etc/environment. SSH logins do not read the process environment, so appending the variable to /etc/environment gives logins a file they read. (00:28:46)
  • Q: You edit pyproject.toml but leave uv.lock unchanged, then the image build runs uv sync --locked. Predict what happens and what you need to do before the build succeeds.
    • A: The build fails because --locked stops when uv.lock and pyproject.toml are out of sync. Run uv sync to update uv.lock, then build again so the image only uses packages that match the project file. (00:29:15)
  • Q: You run the container on a Linux laptop and the mounted SSH key prevents sshd from accepting the connection. What commented-out Dockerfile line should you uncomment?
    • A: Use RUN echo "StrictModes no" > /etc/ssh/sshd_config.d/container.conf. It tells sshd to relax strict key-file ownership checks for the mounted key. (00:29:54)
  • Q: You need uv add to write exact version pins instead of open-ended lower bounds. What [tool.uv] setting does the demo pyproject.toml use?
    • A: Use add-bounds = "exact". It tells uv add to use == instead of >= when adding a dependency. (00:31:24)
  • Q: Your project must use Python 3.14, while another teammate’s project uses an older Python version. Which project file keeps uv from changing the machine-wide Python?
    • A: Use .python-version, which contains 3.14 for this project. It tells uv which Python to download for that project, so different projects can use different Python versions without changing the whole machine. (00:32:48)
  • Q: You run docker build --tag docker-uv-renv . from the project root. What does the trailing dot mean, and what file must Docker find there?
    • A: The dot is the current working directory, and Docker looks for a file named Dockerfile in that directory. That is why the demo builds the image from the root project folder where the Dockerfile lives. (00:35:13)
  • Q: Inside the container, typing python gives command not found. How do you open the Python interpreter that has the project packages?
    • A: Run uv run python. The image installs Python through uv, so the project interpreter and packages come from the uv environment rather than a bare python on PATH. (00:37:52)
  • Q: You type docker run --rm -v "$(pwd):/workspace" -it bash and Docker starts pulling bash:latest. What went wrong, and what is the correct command to open a shell in the demo image?
    • A: The image name is missing, so Docker treats bash as the image name. Use docker run --rm -v "$(pwd):/workspace" -it docker-uv-renv bash to start a shell in the docker-uv-renv image. (00:42:44)
  • Q: You run touch hello.py inside the container’s /workspace while the project folder is mounted. What does the host immediately show, and why?
    • A: The host shows hello.py in the project folder because -v "$(pwd):/workspace" shares the same folder between the host and the container. Changes on one side are reflected on the other side. (00:43:06)
  • Q: You have validation.py open in Positron on the host and also open it in the container. What mistake should you avoid before editing, and why?
    • A: Do not save both sides without refreshing, because there is no automatic Git-style merge and the last save can silently overwrite the other side’s changes. Use the editor’s “revert file” or refresh the file before editing it. (00:44:15)
  • Q: You are deciding whether to store your SSH key in the image or mount it only while the container runs. Why is mounting it the safer choice?
    • A: An SSH key is a credential that can be used to act as you, so baking it into the image exposes it to anyone who pulls the image. Mounting keeps the key out of the image and present only while the container runs. (00:41:50)

2. Docker Compose lifecycle, one-off commands, and Remote SSH (33 Containers: Docker Compose)

00:44:42–01:08:33

  • Q: You copied docker-compose.yml into the project and it defines service analysis-env. In order, what commands build the image and start the service in the background?
    • A: Run docker compose build, then docker compose up --detach. build uses the file’s build: . and image name; up --detach starts the service without giving the terminal prompt inside. (00:53:07)
  • Q: Your compose file maps ports: - "2222:22" for the SSH service. From your laptop, which port do you connect to, and what is listening on port 22 inside the container?
    • A: Connect to port 2222 on your machine; the container’s SSH server listens on port 22. The first number is the host side, and the second number is the container side. (00:48:04)
  • Q: Your compose file includes ~/.ssh/id_ed25519.pub:/root/.ssh/authorized_keys:ro. What does this mount allow, and what does ro mean?
    • A: It mounts the host’s SSH public key into the container as the authorized key for root login. ro makes it read-only inside the container, so the credential is not baked into the image and cannot be modified there. (00:50:13)
  • Q: You run docker compose exec 2026-11-25-docker-validate-analysis-env-1 bash and get service "..." is not running. What command did the demo use to enter the running container, and why?
    • A: Use docker compose exec analysis-env bash. Compose commands use the service name from docker-compose.yml, not the long generated container name shown by docker ps. (00:55:59)
  • Q: You are inside the container and type docker compose down, receiving bash: docker: command not found. What do you do to stop and remove the project container and network?
    • A: Type exit to return to the host, then run docker compose down on the host. The container does not contain the Docker CLI, so compose commands are run on the machine managing Docker. (00:57:23)
  • Q: You need a one-off Python session from the analysis-env service and do not want to leave a long-running container. What command works, and why does docker compose run --rm analysis-env python fail?
    • A: Use docker compose run --rm analysis-env uv run python. --rm deletes the container after the command finishes, and plain python is not on PATH because the project’s Python and packages live in the uv environment. (00:59:04)
  • Q: You want to confirm that a Quarto report renders using the exact environment in the container. What compose command pattern do you run from the project folder?
    • A: Run docker compose run --rm analysis-env uv run quarto render <file>. It starts a new container for the service, runs the report command through uv, and removes the container when the command finishes. (01:00:35)
  • Q: You start the service with docker compose up --detach and want to connect Positron or a VS Code fork through Remote SSH. What host, user, and port do you enter?
    • A: Use root@localhost on port 2222. root is the username in the container prompt, and 2222 is the host port mapped to the container’s port 22. (01:03:06)
  • Q: You notice several containers are running and your laptop memory is filling up. What command stops and removes the containers and network defined by the compose file?
    • A: Run docker compose down. It reads the compose file, stops and removes the project’s container and network, and frees the memory the containers were using. (00:57:38)
  • Q: You have a docker-compose.yml for a self-hosted service and want to start it in the background. What short flag can replace --detach?
    • A: Use docker compose up -d. The -d flag is the short form of --detach, so the service runs in the background and the terminal returns. (01:08:04)
  • Q: A compose file maps 8888:8888 for a JupyterLab service. If a teammate changes it to 9000:8888, what changes for the person connecting from their laptop?
    • A: The laptop connection changes to port 9000, while the service inside the container still listens on 8888. The first number is always the host port to use. (00:49:13)

3. Data validation with pointblank (41 Data validation: Python (pointblank))

01:08:33–01:20:48

  • Q: Your uv add pandera pointblank command fails with Project is missing a [project] table. How do you still add the validation packages and install them?
    • A: Add pandera, palmerpenguins, and pointblank to the dependencies list in pyproject.toml by hand, then run uv sync. uv sync resolves and installs the packages and creates or updates uv.lock. (01:09:59)
  • Q: You need the Palmer penguins data for a pointblank check. What import and assignment load the data into penguins?
    • A: Use from palmerpenguins import load_penguins and then penguins = load_penguins(). Import pointblank as pb before running the validation functions. (01:11:19)
  • Q: Before writing value checks, you need a quick report of where missing values are in penguins. What pointblank call do you run?
    • A: Run pb.missing_vals_tbl(data=penguins). It reports missing values by column, broken into row sections so you can see where missingness is concentrated. (01:12:47)
  • Q: You create a validation with thresholds=(0.01, 0.05, 0.10) and 6% of the rows in a step fail. What level does the report show for that step?
    • A: It shows an error flag. The thresholds mean warning at 1%, error at 5%, and critical at 10%, so 6% crosses the error threshold but not the critical threshold. (01:14:20)
  • Q: You add .col_vals_in_set(columns="species", set=["Adelie", "Chinstrap"]) to a validation that includes the full penguins data. Predict what happens to rows with species Gentoo.
    • A: Those rows fail the step because Gentoo is not in the allowed set. The report flags the out-of-set values, which is how the demo shows a failing check. (01:18:29)
  • Q: You add .col_vals_between(columns="bill_length_mm", left=30, right=60, na_pass=True) to a value check. What happens to missing bill lengths in this step?
    • A: Missing values pass the step because na_pass=True tells pointblank not to treat missingness as a range failure. This keeps value checks separate from missing-value checks. (01:18:52)
  • Q: You suspect duplicate rows from two people coding the same record. What method do you chain onto the validation to check that each row is different?
    • A: Chain .rows_distinct(). It adds a step that fails when identical rows appear in the data. (01:16:52)
  • Q: You have built a pb.Validate object with several chained steps, but no checks have run yet. What method do you call to execute all of the steps?
    • A: Call .interrogate(). It runs the stored validation steps and returns the report object with pass/fail information. (01:17:10)
  • Q: After calling .interrogate(), you need one data frame for a teammate who will build the model and another for the person fixing bad rows. What calls produce those two frames?
    • A: Use values.get_sundered_data(type="pass") and values.get_sundered_data(type="fail"). The passing frame can move downstream while the failing frame is used for cleanup. (01:19:36)
  • Q: You want to give the failed penguins rows to a teammate as a standalone data set. How do you save them?
    • A: Save the failed frame to CSV, for example failed.to_csv("penguins_to_fix.csv", index=False). This creates a concrete file the teammate can open and fix. (01:20:32)
  • Q: You have a pipeline with a data-cleaning step and a modelling step. Where should you insert pointblank checks that the data has the values needed by the model?
    • A: Place them right after the cleaning step or right before the modelling step, and use checks in more than one place as the analysis progresses. The checks are assumptions about the data at that point, not one single block. (01:15:31)
  • Q: You have value checks for species and bill length in validation.py. How should missing-value checks be organized relative to those value checks?
    • A: Keep missingness as a separate analysis from the value checks, for example checking per column and per row. That keeps the pass/fail report easier to read because missing values and out-of-range values are different problems. (01:18:52)
