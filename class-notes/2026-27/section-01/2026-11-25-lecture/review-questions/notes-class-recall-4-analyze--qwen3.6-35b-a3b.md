## 2. Volume mounting and container isolation ([33 Containers: Docker Compose](https://ubc-dsci.github.io/reproducible-and-trustworthy-workflows-for-data-science/lectures/containers-docker-compose.html))

*00:18:00–00:27:21*

- **Q:** Differentiate between using `COPY` inside a `Dockerfile` and using the `-v` flag in `docker run` for a project with constantly changing analysis files. How does this distinction affect version control workflows and credential security?
    - **A:** `COPY` in the `Dockerfile` only transfers files at build time, meaning any changes to analysis files would require rebuilding the entire container image to be reflected. In contrast, the `-v` flag mounts a local volume directly into the container, creating an immediate two-way sync that updates instantly without rebuilds. This approach preserves the host's version control workflow, allowing standard `git` commands to run locally. It also secures credentials because sensitive files like SSH keys can be mounted as read-only volumes (`:ro`) only during runtime, preventing them from being baked into the image or exposed to others who pull the repository. *(00:39:55, 00:40:29, 00:40:50, 00:50:19)*

    - **A:** Both approaches execute code within the isolated container environment to guarantee reproducibility, but they differ in execution flow. `docker compose run --rm analysis-env uv run python` spins up a temporary container, executes the command, and tears it down, which is ideal for one-off reproducibility checks like rendering reports.
