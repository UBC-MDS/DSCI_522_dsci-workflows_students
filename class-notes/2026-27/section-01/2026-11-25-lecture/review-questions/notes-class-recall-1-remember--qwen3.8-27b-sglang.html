8. Mounting the project folder with -v (33.1 Docker Compose to launch containers)

00:38:22–00:44:42

  • Q: Which flag mounts a volume in docker run?
    • A: -v. (00:38:52)
  • Q: What mount command did the instructor use to bring the host folder into the container?
    • A: docker run --rm -v "$(pwd):/workspace" -it docker-uv-renv bash. (00:38:52)
  • Q: What does $(pwd) refer to in that command?
    • A: The current working directory on the host, mapped to /workspace in the container. (00:39:09)
  • Q: How did the instructor demonstrate that the mount is two-way?
    • A: He ran touch hello.py inside the container, and hello.py immediately appeared on the host too. (00:43:04)
  • Q: What does the instructor compare the mounted folder to?
    • A: A network share drive where both sides work on the same files. (00:43:15)
  • Q: What must you be careful about when editing the same file on the host and in the container at the same time?
    • A: Whoever saves last silently overwrites the other side’s changes — like a Git conflict without Git; refresh with the editor’s “revert file” before editing. (00:43:59)
  • Q: What reason did the instructor give for mounting the folder instead of COPYing the files into the image?
    • A: COPY freezes the files at build time, so changing files would force a full rebuild; mounting keeps files in sync without rebuilding. (00:40:18)
  • Q: What reason did the instructor give for doing Git on the host rather than in the container?
    • A: To GitHub the container is a brand-new machine (no token/SSH key, and it resets when turned off), so you run git add / git commit / git push on the host. (00:41:38)
  • Q: What reason did the instructor give for not baking your SSH key into the image?
    • A: Your SSH key is like the password to your account; you do not want anyone who pulls the container to be able to read it. (00:41:50)
  • Q: When did the instructor say it is acceptable to copy files into the image instead of mounting them?
    • A: For the final submitted / compliance version where the container must stand alone. (00:42:20)

9. docker-compose.yml: putting the launch in a file (33.1 Docker Compose to launch containers)

00:44:42–00:55:31

  • Q: What new file did the instructor introduce?
    • A: docker-compose.yml. (00:44:46)
  • Q: What reason did the instructor give for using a compose file instead of a long docker run command?
    • A: docker run commands get very long with many flags and are hard to edit in a terminal; the compose file keeps all parameters in a documented, version-controlled file. (00:46:07)
  • Q: What top-level key does the file begin with?
    • A: services:. (00:46:18)
  • Q: What is the name of the single service in the file?
    • A: analysis-env. (00:46:24)
  • Q: What image does that service come from?
    • A: docker-uv-renv (the image built earlier). (00:46:31)
  • Q: What do build: . together with image: docker-uv-renv mean?
    • A: If the image does not exist, build it from the Dockerfile in this folder and name it docker-uv-renv (the compose equivalent of docker build --tag docker-uv-renv .). (00:47:06)
  • Q: What port mapping is in the file, and which side is which?
    • A: 2222:22 — 2222 on your computer maps to 22 in the container (where sshd listens). (00:47:55)
  • Q: What reason did the instructor give for mapping to 2222 on the host instead of 22?
    • A: Because 22 is a common port already used for real things, so you do not want to overwrite it. (00:49:03)
  • Q: Which number in a port map is the one you connect to on your machine?
    • A: The first number; the two numbers do not have to match. (00:49:13)
  • Q: What does the second volumes: entry mount, and how?
    • A: Your SSH public key (~/.ssh/id_ed25519.pub) to /root/.ssh/authorized_keys, read-only (:ro). (00:50:13)
  • Q: What happens when you turn a container off and on again without a mounted volume?
    • A: It resets to what was built; nothing is saved (only a mounted volume preserves files). (00:50:28)
  • Q: What command runs the build from the compose file?
    • A: docker compose build (essentially docker build -t <name>). (00:53:07)
  • Q: What command starts the container in the background?
    • A: docker compose up --detach. (00:53:39)
  • Q: What does --detach mean?
    • A: Start it but do not give you the prompt inside; it runs in the background and you get your terminal back. (00:54:12)
  • Q: What did docker ps -a show for the running container’s name and port forward?
    • A: Name 2026-11-25-docker-validate-analysis-env-1 and forward 0.0.0.0:2222->22/tcp. (00:54:52)
