## 2. Building a Python Container with `uv` ([30 Python packages with uv in an image](https://ubc-dsci.github.io/reproducible-and-trustworthy-workflows-for-data-science/lectures/containers-uv.html))

- **Q:** You are writing a `Dockerfile` to set up a Python project. Instead of relying on system package managers to install `uv`, you want to pull the exact binaries directly from Astral's registry. How do you write a `COPY` instruction to install `uv` and `uvx` into the container's PATH?
    - **A:** Use `COPY --from=ghcr.io/astral-sh/uv:0.13.7 /uv /uvx /usr/local/bin/`. This multi-stage copy pulls the specific `uv` binaries from Astral's official registry and places them directly into the container's executable PATH. *(00:24:53)*

- **Q:** You add a new dependency to your project locally using `uv add pandas`. When you rebuild the Docker image, you want to guarantee that the build stops immediately if your local `uv.lock` file does not match `pyproject.toml`. Which flag must you append to your `uv sync` command in the `Dockerfile`?
    - **A:** Append `--locked` to the `uv sync` command (e.g., `RUN uv sync --locked`). This flag forces `uv` to strictly verify that the lockfile matches the project metadata, halting the build with an error if they are out of sync. *(00:38:26)*

- **Q:** You want to ensure that every package added to your project via `uv add` is pinned to an exact version (e.g., `==6.1`) rather than a lower bound (e.g., `>=6.1`). What configuration must you add to the `[tool.uv]` section of your `pyproject.toml` file?
    - **A:** Add `add-bounds = "exact"` inside the `[tool.uv]` table in `pyproject.toml`. This setting forces `uv add` to write strict exact version pins instead of the default lower bounds, ensuring long-term reproducibility. *(00:31:31)*

## 3. Layer Caching and `Dockerfile` Optimization ([29.1.3 Layer caching](https://ubc-dsci.github.io/reproducible-and-trustworthy-workflows-for-data-science/lectures/containers-building.html#layer-caching))

*00:33:35–00:51:21*

- **Q:** Your `Dockerfile` takes a long time to build because it runs `uv sync` early on. You recently changed a single line of Python code in `hello.py`. If `hello.py` is copied into the image before the `RUN uv sync` step, how does Docker's layer caching affect your rebuild time?
    - **A:** Docker will discard the cached `uv sync` layer and rebuild it entirely because a preceding `COPY` step changed. Since `uv sync` is computationally expensive, this forces a full reinstall of dependencies every time you edit your code. *(00:41:53)*

- **Q:** You want to minimize rebuild times for a project where configuration and dependency installation rarely change, but application code changes frequently. In what order should you arrange the `COPY` and `RUN` instructions in your `Dockerfile` to leverage Docker's caching effectively?
    - **A:** Place the static setup steps (like `COPY pyproject.toml uv.lock` and `RUN uv sync`) at the top of the file, and place the `COPY` instructions for your application code at the bottom. This way, changes to your code only invalidate the final layers, leaving the expensive dependency installation cached. *(00:42:40)*

- **Q:** You decide to snapshot your entire project folder into the image by adding `COPY . /workspace` to your `Dockerfile`. Why is this approach problematic for active exploratory data analysis, and what workflow burden does it create when you edit a script?
    - **A:** This approach snapshots a static version of your files, so any edits you make on your host machine will not reflect inside the container until you rebuild the entire image. This defeats rapid iteration during analysis and forces you to commit and rebuild every time you tweak a script. *(00:50:14)*

## 4. Volume Mounting and Cross-Platform Environments ([28.1.2 Mounting volumes to containers](https://ubc-dsci.github.io/reproducible-and-trustworthy-workflows-for-data-science/lectures/containers-running.html#mounting-volumes-to-containers))

*00:51:21–01:06:55*

- **Q:** You are actively developing a Python project and want to edit scripts on your host machine while testing them inside a Linux container. Which `docker run` flag and syntax should you use to mount your current directory into the container at `/workspace`?
    - **A:** Use the `-v` flag with the syntax `-v "$(pwd):/workspace"`. This mounts the current working directory from your host machine directly into the container's `/workspace` path, creating a live, bidirectional sync. *(00:54:18)*

- **Q:** After mounting your local project directory into a container, you run `uv run hello.py` and receive an error about binary incompatibility. You realize the container is trying to execute a `.venv` folder that was copied from your macOS machine. How do you prevent `uv` from using the mounted local virtual environment?
    - **A:** Add `ENV UV_PROJECT_ENVIRONMENT=/opt/venv` to your `Dockerfile` before running `uv sync`. This environment variable forces `uv` to install and look for packages in `/opt/venv` inside the container, completely ignoring the mounted local `.venv` folder. *(00:53:59)*

- **Q:** You have set up `UV_PROJECT_ENVIRONMENT=/opt/venv` in your Dockerfile. You run a container with a mounted volume and want to verify that `uv` is correctly ignoring your host's `.venv` and using the container's isolated Linux environment. Which command should you run inside the container to check the Python executable's path?
    - **A:** Run `uv run which python` inside the container. The command will output `/opt/venv/bin/python`, confirming that `uv` is ignoring the mounted local virtual environment and using the isolated, Linux-compiled packages. *(01:06:12)*

    - **A:** The file must be named `docker-compose.yml`. Inside the file, the `services:` top-level key lists the individual containers (e.g., `analysis-env:`) and their configurations. *(01:07:43)*

- **Q:** You have a `docker-compose.yml` file that builds your image and mounts your local directory. You want to build the image exactly as specified in the compose file without typing out the full `docker build` command. Which command should you run from your project folder?
    - **A:** Run `docker compose build`. This command reads the `docker-compose.yml` file, locates the `build: .` instruction, and compiles the image using your `Dockerfile`. *(01:11:28)*

- **Q:** You are submitting your milestone project and need to ensure the container runs your analysis automatically.
