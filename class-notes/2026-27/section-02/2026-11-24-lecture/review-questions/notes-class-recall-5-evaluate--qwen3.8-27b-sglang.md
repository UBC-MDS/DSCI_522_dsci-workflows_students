## 7. Pinning package versions in `pyproject.toml` ([22 uv: pinning exact versions](https://ubc-dsci.github.io/reproducible-and-trustworthy-workflows-for-data-science/lectures/virtual-environments-python-uv-exact-pins.html))

*00:27:40–00:34:45*

- **Q:** A milestone project’s `pyproject.toml` declares `cowsay>=6.1` and relies on `uv.lock` to keep version 6.1. Is that acceptable for a long-running analysis?
    - **A:** No, not for a long-running analysis. A `>=` lower bound can let a later major version, such as `cowsay` 7.0, be pulled during a rebuild, and a major version change is typically backwards incompatible. The class solution is to pin the packages that matter with `==` in `pyproject.toml` and set `add-bounds = "exact"` so `uv add` keeps writing exact pins. *(00:31:06)*

## 9. Dockerfile layer order and caching ([29.1.3 Layer caching](https://ubc-dsci.github.io/reproducible-and-trustworthy-workflows-for-data-science/lectures/containers-building.html#layer-caching))

*00:39:25–00:44:30*

- **Q:** A `Dockerfile` copies `hello.py` before `RUN uv sync --locked`. Would you approve that order for a project where scripts change often?
    - **A:** No, I would not approve that order for frequently changing code. Docker reuses cached layers, but a change to an earlier layer reruns that layer and everything below it.
