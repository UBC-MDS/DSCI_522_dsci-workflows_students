## 4. Branch cleanup and safe deletion ([8 Git branches](https://ubc-dsci.github.io/reproducible-and-trustworthy-workflows-for-data-science/lectures/git-branches.html))

*00:52:17–01:03:51*

- **Q:** After merging your feature branch into `main` on GitHub, your local repository still lists the remote branch. You want to clean up your workspace. Is it safe to run `git branch -D` to delete your local branch, and what is a safer alternative the class demonstrated?
  **A:** Verdict: It is not safe if you want to avoid accidental data loss. Criterion: Use the lowercase `d` flag (`git branch -d`), which safely deletes only merged branches and prevents you from permanently losing work if you mistakenly target an unmerged branch. *(01:02:46)*

- **Q:** A teammate asks why their local Git history still shows tracking references for branches that have already been merged and deleted on GitHub. Which single command would you recommend they run to clean up these stale local references before deleting the local branches themselves?
  **A:** Verdict: Run `git fetch --prune`. Criterion: This command synchronizes the local repository with the remote and automatically removes local tracking references for branches that no longer exist on the remote, keeping the workspace clean without altering local files. *(01:01:30)*

Is your work considered complete for the Pull Request, and what criterion from the class ensures your code remains functional?
  **A:** Verdict: No, your work is not necessarily complete. Criterion: Fixing a conflict marker only resolves the immediate syntax clash; you must verify that the entire codebase still runs correctly, as dependencies, variable names, or logic may have shifted elsewhere during the merge. *(01:11:21)*

- **Q:** After successfully rebasing your branch to resolve conflicts locally, you attempt to push the changes to the remote repository but receive an error rejecting the push. Why is a standard push failing in this situation, and what command must you use instead?
  **A:** Verdict: A standard push fails because rebasing rewrites the local commit history, which conflicts with the remote history. Criterion: You must force-push using `git push --force-with-lease` to safely update the remote branch with your rewritten history without overwriting concurrent work added by others. *(01:19:47)*
