  • Q: Name the command that sends commits up to GitHub and the one that brings teammates’ commits down. A: git push sends commits up, and git pull brings commits down. (00:11:33)

5. What a branch is: main, HEAD and origin/main

00:12:03–00:17:54

  • Q: What is the main branch? A: The default branch you work on. (00:12:38)

  • Q: What happens to the main branch each time you commit while HEAD is attached to it? A: main moves forward (increments) with each commit. (00:13:17)

  • Q: What does origin/main represent? A: The remote: what your computer thinks the state of main on GitHub is. (00:13:30)

  • Q: Define a branch as the instructor described it. A: A name you choose yourself that moves forward when you commit, instead of main moving. The git add/git commit process stays the same. (00:13:55)

  • Q: What did the instructor say the main branch should be treated as? A: The production or final version: the stable place where at least the code works. (00:15:10)

  • Q: Do you need collaborators to use branches? A: No. Branches are useful when working alone too, to section off work. (00:16:05)

  • Q: What real project did the instructor say he edited entirely in branches, and why? A: The course textbook. Another instructor was teaching from it that day, and he didn’t want pages moving around mid-lecture. (00:16:37)

  • Q: Which two DSCI 521 commands did the instructor name as another way to undo work, besides using branches? A: git reset and git revert. (00:17:22)

  • Q: What does the -c flag in git switch -c <name> stand for, and what does the command do? A: -c is for create. The command creates a new branch and moves HEAD to it. (00:20:09)

  • Q: Roughly when was git switch introduced, replacing part of what git checkout did? A: Around 2019 to 2020. (00:26:59)

  • Q: Which command does the instructor use himself day to day, and when does he use switch? A: He uses git checkout. He only uses switch when teaching. (00:26:59)

  • Q: Besides moving HEAD, what else did git checkout do? A: Much of what restore and revert do. Those newer commands came out of checkout, and checkout still has those behaviours. (00:27:09)

  • Q: What should you ask an AI tool to do if it tells you to run a checkout command you don’t understand? A: Ask it to do the same thing with switch instead. (00:27:44)

  • Q: Name the git checkout equivalent of git switch -c <name>. A: git checkout -b <name>. (00:28:10)

  • Q: What does git branch <name> do, and what doesn’t it do? A: It creates the branch but doesn’t move you to it. You still have to checkout or switch afterwards. (00:28:13)

15. When a merge creates the conflict: resolving on GitHub (8.3 What happens when my feature branch falls behind main?)

01:10:00–01:12:44

  • Q: What does GitHub do to other pull requests targeting main when one of them is merged? A: It rechecks each one to see whether it can still be merged. (01:10:19)

  • Q: Which GitHub tool can resolve simple conflicts without your local computer? A: The web editor. (01:10:54)

  • Q: Name the three conflict markers you look for when fixing a conflict. A: Less-than, equals and greater-than markers: <<<<<<<, ======= and >>>>>>>. (01:10:59)

  • Q: State what “fixing” a conflict means for code in this course. A: Your code must work from top to bottom again, not just have the markers removed. A conflict on line 13 can still break something on line 50. (01:11:21)

16. Resolving the conflict locally with rebase (8.3.2 Using rebase)

01:12:44–01:20:42

  • Q: Which Git command does the instructor use to fix conflicts on a branch locally? A: git rebase. (01:14:04)

  • Q: Define what a rebase does, in the instructor’s words. A: It replays your branch’s commits on top of the existing changes. (01:14:31)

  • Q: What two commands synced main before the rebase? A: git switch main, then git pull origin main. (01:16:25)

  • Q: What two commands started the rebase of the conflicting branch? A: git switch dan-delete, then git rebase main. (01:17:01)

  • Q: What did git rebase main print when it hit the conflict? A: CONFLICT (content): Merge conflict in README.md, followed by error: could not apply cb810d5... branch -d and -D. (01:17:14)

  • Q: How did the instructor resolve the README.md conflict? A: He kept both definitions and cleaned up some whitespace. (01:17:46)

  • Q: In DSCI 521, which command triggered merge conflicts, compared with the one used here? A: In 521 it was git pull origin main. Here it was git rebase main. (01:17:56)

  • Q: Which option gets you out of a rebase if something goes wrong? A: git rebase --abort. (01:18:20)

  • Q: After fixing the conflict markers, which two commands completed the rebase? A: git add README.md to mark the resolution, then git rebase --continue. (01:18:32)

  • Q: What exact command pushed the rebased dan-delete branch? A: git push --force-with-lease origin dan-delete. (01:19:34)

  • Q: What error came from the first attempt at the force push? A: error: unknown option `force-with-leasse' because the option was misspelled. (01:19:34)

  • Q: What did the successful force push print for dan-delete? A: + cb810d5...0e16503 dan-delete -> dan-delete (forced update). (01:19:47)

  • Q: After a rebase, can you push without forcing, and what does GitHub show afterwards? A: No. You can’t avoid a force push, because the rebase changed the branch’s history. GitHub then records that a force push happened. (01:20:17)

  • Q: How did the instructor describe a force push after a rebase, in compliance terms? A: You’ve “mangled history”. (01:20:21)

  • Q: Which two commands clean up locally after a rebased pull request is merged? A: git fetch --prune and git branch -d. (01:20:35)
