Some data science conventions

  • 🐍 Use snake_case for all folder & file names (lowercase + underscore)
  • Use Markdown for documentation.
    • Need a review? Here is the markdown tutorial
  • yaml (.yml or .yaml) files for data storage and system configurations (NOT for documentation)
    • YAML = Yet Another Markup Language
    • No use of strict symbols (e.g., braces, square brackets)
    • Use # for comments
    • Python style indentation using whitespace (NOT TABS)
    • JSON is subset of YAML. JSON file can be parsed by a YAML parser.

Demo: put our uv environment into our own image

python:3.14-slim has Python but no pandas. We write a Dockerfile that copies in our three uv files and runs uv sync inside the image.

  • Textbook: Customizing and building containers
  • uv in Docker: uv docs

Terminal, step by step (tested with uv 0.12.10 and Docker 29.7.2):

  1. cd ~/Desktop/github/dsci522
  2. mkdir dockerfile_demo
  3. cd dockerfile_demo
  4. uv init --bare → only pyproject.toml.
  5. uv python pin 3.14 → .python-version. It matches the Python inside python:3.14-slim.
  6. uv add pandas pandera → creates .venv/ and uv.lock. Point out: pandas 3.1.1, pandera 0.36.0.
  7. ls -a → .python-version, .venv, pyproject.toml, uv.lock.
  8. nano Dockerfile, paste the Dockerfile from the slide, then Ctrl + X, Y, Enter. (Or open the folder in VS Code with code .)
  9. cat Dockerfile → walk through it line by line with the highlights on the next slide.
  10. docker build --tag dockerfile_demo . → point at the dot: “build from this folder”. Point at the RUN uv sync --locked step in the output: uv installs the packages inside the image.
  11. docker images dockerfile_demo → about 410 MB.
  12. docker run --rm dockerfile_demo python -c "import pandas, pandera; print(pandas.__version__, pandera.__version__)" → 3.1.1 0.36.0, the same versions as in uv.lock.
  13. docker run --rm -it dockerfile_demo bash → now inside the container. Type ls -a → only the three uv files, no .venv/ (the environment lives in /opt/venv). Type which python → /opt/venv/bin/python. Type exit.
  14. Ask: what happens if a teammate runs uv add requests but forgets to rebuild the image? Answer: the image still has the old environment. Rebuild after every change to uv.lock.

The Dockerfile, line by line

FROM python:3.14-slim

COPY --from=ghcr.io/astral-sh/uv:0.13.7 /uv /uvx /usr/local/bin/

WORKDIR /home/project
ENV UV_PROJECT_ENVIRONMENT=/opt/venv
COPY pyproject.toml uv.lock .python-version ./
RUN uv sync --locked
ENV PATH="/opt/venv/bin:$PATH"

Click through the highlights:

  1. FROM: start from an image that already has Python 3.14. Never latest.
  2. COPY --from: copy the uv program out of uv’s official image. No need to install it.
  3. WORKDIR: the folder inside the image where the next commands run (like cd).
  4. ENV UV_PROJECT_ENVIRONMENT: put the environment in /opt/venv instead of .venv/, so it is not hidden when we mount our project folder over /home/project with -v.
  5. COPY: the shopping list, the receipt and the Python version. Not .venv/: the electronics are bought again inside the image, with chargers for Linux.
  6. RUN uv sync --locked: build the environment from uv.lock. --locked stops the build if uv.lock does not match pyproject.toml.
  7. ENV PATH: so typing python finds the environment’s Python without uv run.
