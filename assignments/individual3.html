Individual assignment 3

Summary

This assignment is hands-on practice with Quarto reports, which you will use for your project report. You get a short, messy report and turn it into a polished one: Quarto numbers the figures and tables, builds the table of contents and the reference list, and fills in numbers from your code, so you never update them by hand.

TipReadings for this assignment
  • Textbook: Reproducible reports with Quarto
  • Quarto cheatsheet: the code we ran in class for this assignment, step by step
  • For the bonus: Quarto and GitHub Pages (DSCI 521 notes)

Instructions

  1. Make the repository. Open the Python template or the R template, click Use this template > Create a new repository, and make a public repository under your personal account (not under UBC-MDS). Clone it and cd into it.

  2. Start the container. Open Docker Desktop, then run docker compose up in the repository folder. It gives you JupyterLab (Python) or RStudio (R) with everything installed (see below).

  3. Make the figures and table. In the terminal inside JupyterLab or RStudio, run the script (command below). New plots and a .csv file appear in results/.

  4. Make the 7 edits to reports/qmd_example.qmd. The Syntax you need section below has an example of each.

    1. Headers and table of contents: turn the plain section names (Aim, Data, Methods, Results, References) into # headers, and add a table of contents to the YAML header.
    2. References: point the YAML header at references.bib, and replace each hand-typed citation (e.g. “Van Rossum and Drake 2009”) with a citation key.
    3. Figures: give both figures a caption and a #fig- label, and make the second one 60 to 70% wide.
    4. Table: give the table a tbl- label and a caption.
    5. Cross-references: replace every hard-coded “Figure 1”, “Table 1” and so on in the text with a cross-reference such as @fig-horse-pop.
    6. Inline code: replace the ??? in the text with inline code that prints largest_sd.
    7. Hide the code: set echo: false so the rendered report shows figures and tables, but no code.

  5. Render the report to HTML and PDF (commands below) and open both to check your edits. Then commit and push.

  6. Optional bonus: GitHub Pages. Publish the HTML report on the web (steps below).

  7. Clean up. Press Ctrl + C in the terminal where you ran docker compose up, then run docker compose rm.

TipSyntax you need (step 4)

YAML header (edits 1, 2 and 7), at the top of qmd_example.qmd. This is what it looks like when you’re done:

---
title: "DSCI 310: Historical Horse Population in Canada"
author: "Tiffany Timbers & Jordan Bourak"
editor: source
format:
  html:
    toc: true
    toc-depth: 3
  pdf:
    toc: true
    toc-depth: 3
bibliography: references.bib
execute:
  echo: false
---

Delete the old format: html line: a setting can only appear once.

Headers (edit 1): # Aim, # Data, # Methods, # Results, # References.

Citations (edit 2): put the key in square brackets after @. Separate several keys with ;.

Horse population data were sourced from the
[Government of Canada's Open Data website](http://open.canada.ca/en/open-data) [@horses1; @horses2].

Only references you cite show up in the reference list.

Figures (edits 3 and 5): caption in the square brackets, label and width in the curly brackets, then refer to the label in the text. Delete the old “Figure 1: …” line under the image.

We can see from @fig-horse-pop that Ontario, Saskatchewan and Alberta ...

Table (edits 4 and 5): add a label and caption as the first lines of the code cell that makes the table, and delete the old “Table 1. …” line above it.

TipOptional bonus: publish on GitHub Pages (step 6)

  1. In the root of your repository, create _quarto.yml with:

    _quarto.yml
    project:
  type: website
  output-dir: docs

  2. Also in the root, create an empty .nojekyll file (touch .nojekyll). It tells GitHub Pages to serve your files as they are.

  3. From the root, run quarto render. The rendered site lands in docs/. Check that docs/ contains index.html and .nojekyll (ls -a docs).

  4. Commit and push, including docs/.

  5. On GitHub, go to Settings > Pages. Under Source pick Deploy from a branch, then pick the main branch and the /docs folder, and click Save.

  6. Wait a few minutes and refresh: the page shows the link to your live report.

TipTroubleshooting
  • A YAML error when you render: indent with 2 spaces (not 4, not a tab), and put a : after every setting name.
  • A setting seems ignored: check it appears only once in the YAML header (e.g. no leftover format: html).
  • The reference list is empty: you haven’t cited anything yet. Add [@key] citations in the text.
  • @fig-... or @tbl-... shows as “?@fig-…”: labels must start with fig- or tbl- and use -, not _ (fig-horse-pop, not horse_pop).
  • The PDF fails but the HTML works: read the error message for the line number, and check special characters in your captions.
