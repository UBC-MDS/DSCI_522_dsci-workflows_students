Bonus: Project website

Bonus summary

This optional bonus turns your whole project into a Quarto website on GitHub Pages, at the same URL as the report you published in Milestone 2.

ImportantUp to 5 bonus points, for your team

The points go to Milestone 4 unless you tell us otherwise when you submit. They can make up for points lost on that milestone, but can’t take it above its maximum. It is due with Milestone 4 (see the syllabus), and we grade it from the same 3.0.0 release, so your Milestone 4 README instructions must still work exactly as written.

TipReadings for this bonus
  • Introduction to Quarto and GitHub Pages (DSCI 521): the same setup, read it again first
  • Quarto: includes and alt text for figures

1. Turn your project into a website

  1. Edit _quarto.yml in the root of your repository: add type: website and output-dir: docs, list the website’s pages under render, and add a website section with the menu bar (example below). Keep your existing format settings (such as embed-resources and PDF): they still apply to your report.
  2. Give each new page format: html in its YAML header, so Quarto doesn’t also make a PDF of it.
  3. Add an empty .nojekyll file to the root of your repository (Quarto copies it into docs/), and add .quarto/ to your .gitignore.
  4. Clean up the old report: it now renders to docs/reports/<your-report>.html and .pdf, with the website’s menu bar. Delete the old rendered files from reports/, and update your Makefile and README to the new locations.

quarto render now renders the whole website; quarto render reports/<your-report>.qmd still renders just the report, and quarto preview shows the website as you edit.

TipExample _quarto.yml and folder layout (step 1)

Change the title, the report’s file name and the repository URL to your own.

_quarto.yml
project:
  type: website
  output-dir: docs
  render:          # keeps files like CONTRIBUTING.md out of the website
    - index.qmd
    - about.qmd
    - reports/<your-report>.qmd

website:
  title: "Your project title"
  navbar:
    left:
      - href: index.qmd
        text: Home
      - href: reports/<your-report>.qmd
        text: Report
      - href: about.qmd
        text: About
    right:
      - icon: github
        href: https://github.com/UBC-MDS-2026-27/<your-repository>
        aria-label: GitHub repository

# Keep your existing `format:` settings below.

Only the new and changed parts are shown:

.
├── _quarto.yml           # now a website: renders everything into docs/
├── .nojekyll
├── Makefile
├── README.md
├── index.qmd             # homepage: includes README.md
├── about.qmd             # the team
├── reports/
│   └── <your-report>.qmd
└── docs/                 # the published website (generated, but committed)
    ├── index.html
    └── reports/
        ├── <your-report>.html
        └── <your-report>.pdf

2. Add the pages

  1. Homepage (index.qmd): include your README instead of copying it, so the homepage stays up to date. It needs no title: Quarto uses the README’s first heading.

    index.qmd
    ---
format: html
---

{{< include README.md >}}

  2. About page (about.qmd): for each team member, their name linked to their GitHub profile, and a few sentences in their own words (for example, their background and what interests them in data science). The site is public, so each person decides what to share. A photo is optional.

  3. Report: the Report menu item links to its HTML page, and Quarto adds a link to the PDF on that page. Link to both versions from your README too. Give every figure alt text: the fig-alt option on code cells that make figures, or the fig-alt attribute on images:

    ![Feature densities.](../results/figures/densities.png){#fig-densities fig-alt="Density plots of each feature by class."}
WarningLinks in your README must work on the website too

The website only publishes its pages, not the rest of your repository. A relative link such as CONTRIBUTING.md or src/ works on GitHub but breaks on the website, and Quarto doesn’t warn you. Use the full GitHub URL instead (for example, https://github.com/UBC-MDS-2026-27/<your-repository>/blob/main/CONTRIBUTING.md).

3. One make command builds everything

Extend your Milestone 4 Makefile so that make all, from a fresh clone inside your container, downloads the data, runs your validation checks and the rest of the analysis, then renders the whole website into docs/. make clean removes everything make all creates, including docs/.

  1. Change the rule behind publish so it runs quarto render instead of copying the report (sketch below).
  2. Remove your old rule that renders the report in reports/: the report now renders as part of the website.
  3. List as prerequisites every file the website reads, including your README and the figures and tables your report shows.
  4. Say in your README how to build the website.
TipSketch of the Makefile changes (step 3)

Change the file names to your own:

Makefile
.DELETE_ON_ERROR:

publish: docs/index.html

docs/index.html: _quarto.yml index.qmd README.md about.qmd \
        reports/<your-report>.qmd results/figures/<your-figure>.png
    quarto render

clean:
    rm -rf docs
    # ... and everything else your pipeline creates
  • quarto render empties docs/ first, so no old pages are left over.
  • .DELETE_ON_ERROR: deletes docs/index.html if the render fails partway. Without it, the next make would find docs/index.html and say there is nothing to do.
ImportantA clean build, with no warnings

Before you submit, run make clean and then make all inside your container. Everything should rebuild, and Quarto should print no ERROR or WARN messages (for example, about links it could not find). Messages from other tools, such as Jupyter, don’t count. We grade the bonus by doing the same.

4. Publish on GitHub Pages

  1. Commit docs/, including docs/.nojekyll (check with ls -a docs, and on GitHub.com). It is generated, but GitHub Pages can only publish files in your repository.
  2. Keep the GitHub Pages setting from Milestone 2 (main branch, /docs folder). The homepage is now https://ubc-mds-2026-27.github.io/<your-repository>/, and the report moves to .../reports/<your-report>.html.
  3. Update the report link in your README, and say in your README and in the repository’s About box that the URL is now your project’s website.

Submission instructions

On Gradescope, under the bonus assignment, enter (there is no PDF to make):

  1. the URL of your published website
  2. the URL of your project’s GitHub.com repository
  3. the URL of your 3.0.0 release
  4. which milestone the bonus points should go to (Milestone 4 if you leave it blank)

The usual project expectations apply: GitHub flow with reviewed pull requests, communication in GitHub issues, and meaningful commit messages.

TipRubric

You start at 100% (all 5 bonus points) and lose marks for each problem below. Each 20% is 1 bonus point.

Grade Problem
-20% The website is not published on GitHub Pages from docs/, or the menu bar is missing Home, Report, About or the GitHub icon linking to the repository
-20% The homepage copies the README instead of including it, or a link in it is broken on the website
-20% The report is not a page of the website in both HTML and PDF, the Makefile or README still use its old location, or a figure has no alt text
-20% The about page does not introduce each team member
-20% From a fresh clone, inside the container, make all does not run the whole analysis and build the website, Quarto prints an ERROR or WARN message, or make clean does not remove everything make all creates (including docs/)
