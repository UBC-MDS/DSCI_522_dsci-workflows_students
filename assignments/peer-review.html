Peer review

Peer review summary

You review another team’s data analysis project and write your review in a GitHub issue. You are graded on how specific and useful your feedback is. This one is earlier than the other final deadlines: see the syllabus for the due date.

Afterwards, your team fixes some of the feedback it received: that part is in Milestone 4.

1. Open a review request (as a team)

Before (or at the start of) the lab, one person on your team opens an issue in UBC-MDS/data-analysis-review-2026, chooses the Peer Review Submission issue template and fills it in. The reviewer assignments list who reviews your project.

2. Review a project (on your own)

  1. Find the project you review in the reviewer assignments. If its team hasn’t opened an issue by your lab, contact them.
  2. Read their report on GitHub Pages (their README links to it) and the code in their repository.
  3. In their issue, write your review using the MDS data analysis review checklist: check the boxes, then write at least 3 pieces of constructive feedback under Review Comments. Some overlap with other reviewers is fine, but at least 2 points must be yours alone.
  4. Reply if the team responds: discussion in the issue is welcome.
TipHow to write a good review
  • Be concrete: point to the exact file, line, figure or sentence, and suggest a fix.
  • Be empathetic: write the feedback you would find useful on your own project.
  • Be constructive: build on what works; avoid judgmental words.
  • Be kind: only write what you would say face to face to a friend.
  • Use your own words (see the AI policy).
NoteSection 2: a different order

Section 2’s lab is later in the week, so each student:

  1. creates a new issue in UBC-MDS/data-analysis-review-2026, with the group number you review in its title, so issues can be searched by group;
  2. fills in the review checklist there for that group. This issue is the URL you submit.

You are not assigned an issue, but you can assign yourself one to keep track. To track the feedback your own team must address, open issues in your own repository that link to the review issues.

Submission instructions

On Gradescope, enter (there is no PDF to make):

  1. your GitHub.com username
  2. the URL of the issue that contains your review
TipRubric

You start at 100% and lose marks for each problem below.

Grade Problem
-20% Did not submit GitHub username
-80% The submission has no link to the GitHub issue
-10% The review doesn’t use the review checklist template
-10% At least one comment is vague: it is hard to tell what is wrong or how to improve it
-20% There are fewer than 3 review comments
-20% Fewer than 2 comments are your own (the others repeat another reviewer)
-20% At least two of your comments are very similar to each other
