Individual assignment 4

Summary

This assignment is hands-on practice with GNU Make, which you will use to run your project’s analysis. You get a project that runs every step with one script, runall.sh. You replace that script with a Makefile: a smarter data analysis pipeline that only reruns the steps whose inputs changed.

TipReadings for this assignment
  • Textbook: Data analysis pipelines with GNU Make
  • Makefile cheatsheet: rule syntax, and the code we ran in class for this assignment

Instructions

  1. Make the repository. Open the template repository, click Use this template > Create a new repository, and make a public repository under your personal account named data_analysis_pipeline_practice. Clone it and cd into it.

  2. Start the container and run the script. Open Docker Desktop, then start a terminal inside the container and run bash runall.sh (commands below). Look at what it makes in results/ and report/, then run git status to see which files are new.

  3. Write the Makefile in the root of the repository. Turn each command in runall.sh into a rule, listing as dependencies the data file and the script each step uses. Then add two targets:

    • all: makes everything runall.sh makes, ending with the rendered report
    • clean: deletes everything the pipeline made (and nothing else)

  4. Test it. Run make clean, then make all. Run make all again: Make should say there is nothing to do. Then change one data file (e.g. touch data/isles.txt) and run make all: only the steps that use it should rerun. Finally run make clean and check with git status that the repository is back to how you found it.

  5. Commit and push the Makefile, but not the files it makes.

TipCommands to start the container (step 2)

From your repository folder:

docker compose run --rm ia4

You land in a terminal inside the container, with Python, Quarto and Make installed. Note this is docker compose run, not docker compose up: there is no browser app, just the terminal. Your repository folder is shared with the container, so files you make there show up on your computer too.

bash runall.sh   # run the whole analysis the old way
make all         # later: run your Makefile instead
exit             # leave the container when you are done
TipWhat a rule looks like (step 3) 
Makefile
# target : dependencies
#     command (indented with a TAB)
results/isles.dat : data/isles.txt scripts/wordcount.py
    python scripts/wordcount.py --input_file=data/isles.txt --output_file=results/isles.dat

all and clean don’t make files with those names, so list them as .PHONY:

.PHONY : all clean

The Makefile cheatsheet has more examples.

TipTroubleshooting
  • Makefile: *** missing separator. Stop.: the command line must start with a TAB, not spaces. Turn off “insert spaces for tabs” in your editor for Makefiles.
  • make: Nothing to be done or is up to date: that’s Make working: the target is newer than all its dependencies. Run make clean first, or touch a dependency, to make it run again.
  • A step doesn’t rerun after you edit a script: the script is missing from that rule’s dependencies.
  • make clean deletes a file it shouldn’t: only delete what the pipeline makes. Keep the README.md files in results/ and report/.
