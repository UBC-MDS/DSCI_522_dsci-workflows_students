Individual assignment 2

Summary

This assignment is hands-on practice for Milestone 2: build a Docker image from a Dockerfile, and publish it to Docker Hub with GitHub Actions.

TipReadings for this assignment
  • uv: pinning exact versions or renv: declaring packages in DESCRIPTION
  • Python packages with uv in an image or R packages with renv in an image: what each line of the Dockerfile does
  • uv refresher: DSCI 521 uv lecture notes

Instructions

  1. Make the repository. Create a public GitHub.com repository under your personal account, named dsci522-dockerfile-practice, with a README. Clone it; everything below happens in this folder.

  2. Make a small project with uv or renv, whichever you prefer. It needs at least two packages you haven’t used before, each pinned to an exact version.

    • uv: pyproject.toml lists each package with ==, and Python 3.11 or newer is pinned in .python-version. Commit pyproject.toml, uv.lock and .python-version, but not .venv/.
    • renv: DESCRIPTION lists each package with (== x.y.z), using explicit snapshots. Commit DESCRIPTION, renv.lock, .Rprofile and renv/ (the .gitignore inside renv/ keeps the installed packages out).

  3. Add the Dockerfile. Copy the uv or renv version below into a file named Dockerfile (no file extension) in the root of your repository. It installs your packages exactly as your lock file records them. The comments explain each line. For renv, change 4.6.2 on the FROM line to the R version in your renv.lock.

  4. Test it on your computer. Build the image, then load your packages in a container from it (commands below). Fix problems now: debugging on your computer is much faster than on GitHub Actions.

  5. Publish with GitHub Actions. Set up Docker Hub and the two secrets (see below). Then copy the workflow below into .github/workflows/publish-dockerhub.yml, and change only its IMAGE line to <your-docker-hub-username>/dsci522-dockerfile-practice, all in lowercase. Commit and push.

  6. Check that it worked. The run on the Actions tab finishes with a green check mark, and your Docker Hub repository shows two tags: latest and sha- plus 7 characters.

TipThe Dockerfile (step 3)
  • uv (Python)
  • renv (R)
Dockerfile
# Adapted from docker-uv-renv by Daniel Chen (MIT License)
# https://github.com/chendaniely/docker-uv-renv

# Start from Ubuntu Linux. It has no Python: uv installs it.
FROM ubuntu:24.04

# Copy the uv program into the image (0.13.7 pins uv's version)
COPY --from=ghcr.io/astral-sh/uv:0.13.7 /uv /uvx /usr/local/bin/

# Work in the /workspace folder inside the image
WORKDIR /workspace

# Put the packages in /opt/venv (not in a .venv folder in /workspace)
ENV UV_PROJECT_ENVIRONMENT=/opt/venv

# Copy only the files that list your packages
COPY pyproject.toml uv.lock .python-version ./

# Install Python and the exact packages in uv.lock
# (--locked: stop if uv.lock doesn't match pyproject.toml)
RUN uv sync --locked
Dockerfile
# Adapted from docker-uv-renv by Daniel Chen (MIT License)
# https://github.com/chendaniely/docker-uv-renv

# Start from Ubuntu Linux with R installed.
# Change 4.6.2 to the R version in your renv.lock.
FROM rocker/r-ver:4.6.2

# Install curl: renv downloads packages with it
RUN apt-get update && apt-get install --yes curl

# Work in the /workspace folder inside the image
WORKDIR /workspace

# Put the packages in /opt/renv/library (not in renv/library in /workspace)
RUN echo "RENV_PATHS_LIBRARY=/opt/renv/library" >> /usr/local/lib/R/etc/Renviron.site

# Copy only the files renv needs to install your packages
COPY DESCRIPTION renv.lock .Rprofile ./
COPY renv/activate.R renv/

# Install the exact packages in renv.lock
RUN Rscript -e "renv::restore()"
TipCommands to test your image (step 4)

Open Docker Desktop first. From your repository folder, build the image and give it a name (--tag):

docker build --tag dsci522-test .

Then start a container, load your packages, and remove the container when it finishes (--rm). Replace the package names with yours. If nothing prints, it worked: an error means a package didn’t install.

  • uv (Python)
  • renv (R)
docker run --rm dsci522-test uv run python -c "import cowsay, pyjokes"
docker run --rm dsci522-test Rscript -e "library(cowsay); library(praise)"

Changed your environment? Run docker build again: Docker rebuilds only the steps that changed.

TipThe workflow file (step 5)

Change only the IMAGE line. The comments explain the rest.

.github/workflows/publish-dockerhub.yml
# Builds the image from your Dockerfile and publishes it on Docker Hub.
# Save this file as .github/workflows/publish-dockerhub.yml

name: Publish image to Docker Hub

# When the workflow runs
on:
  # by hand: Actions tab > Publish image to Docker Hub > Run workflow
  workflow_dispatch:
  # on its own: when a push changes one of these files
  push:
    paths:
      - Dockerfile
      - uv.lock
      - renv.lock
      - .github/workflows/publish-dockerhub.yml

env:
  # CHANGE THIS LINE: your Docker Hub username / repository name, in lowercase
  IMAGE: your-docker-hub-username/dsci522-dockerfile-practice

jobs:
  publish:
    # a fresh Linux computer on GitHub (Intel/AMD)
    runs-on: ubuntu-latest
    steps:
      # 1. Copy your repository onto that computer
      - name: Check out the repository
        uses: actions/checkout@v7

      # 2. Log in to Docker Hub with your two repository secrets
      - name: Log in to Docker Hub
        uses: docker/login-action@v4
        with:
          username: ${{ secrets.DOCKER_USERNAME }}
          password: ${{ secrets.DOCKER_PASSWORD }}

      # 3. Build the image with two tags:
      #    latest, and sha- plus the first 7 characters of the commit ID
      - name: Build the image
        run: docker build --tag "$IMAGE:latest" --tag "$IMAGE:sha-${GITHUB_SHA::7}" .

      # 4. Upload both tags to Docker Hub
      - name: Push the image
        run: docker push --all-tags "$IMAGE"

Steps 3 and 4 are the same docker build and docker push you would type on your own computer: GitHub just runs them for you, from the files in your repository.

TipSetting up Docker Hub and the GitHub secrets (step 5)
  1. Create a free Docker Hub account if you don’t have one.
  2. Create a public Docker Hub repository named dsci522-dockerfile-practice.
  3. Create a Docker Hub access token with Read & Write permissions. Copy it somewhere safe: you can only see it once.
  4. In your GitHub repository, add two repository secrets (Settings > Secrets and variables > Actions > New repository secret), with exactly these names, because the workflow looks for them:
    • DOCKER_USERNAME: your Docker Hub username
    • DOCKER_PASSWORD: the access token (not your Docker Hub password)
TipTroubleshooting
  • Git refuses to push the workflow file: your personal access token needs the workflow scope. On GitHub, go to Settings > Developer settings > Personal access tokens, select your token, and tick workflow.
  • The workflow didn’t start: it only starts on its own when a push changes the Dockerfile, a lock file or the workflow file. Run it by hand: Actions tab > Publish image to Docker Hub > Run workflow.
  • The login step fails: check the secret names, and that DOCKER_PASSWORD is an access token with Read & Write permissions.
  • The push step fails with “denied” or “unauthorized”: the IMAGE line must start with your Docker Hub username, all in lowercase.
